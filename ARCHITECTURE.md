# MAD MACHINES — устройство прототипа

Новая сцена изолирована в `Assets/MadMachines/Scenes/Playground.unity`. Существующие `SampleScene`, Т-34-85 и его генератор сохранены. Редакторский генератор создаёт реальные объекты, материалы, меши и настройки оружия; повторное открытие не перезаписывает отредактированную сцену.

## Поток управления

`LocalPlayerInput` читает Unity Input System и передаёт `VehicleCommand` в `VehiclePhysics`. Физика выполняется в FixedUpdate: четыре луча подвески, пружина/демпфер, силы сцепления в точках контакта, поворот передних колёс, ручной тормоз. Шасси остаётся динамическим Rigidbody: может прыгать, крениться и переворачиваться. Колёса — визуальное представление лучей, корпус имеет реальные коллайдеры.

`VehicleCamera` следует за назначенной машиной и задаёт направление наведения. `WeaponSystem` независимо поворачивает точки крепления оружия. `WeaponDefinition` — ScriptableObject, три отдельных ресурса с параметрами. Запрос `RequestFire` проверяет полномочия и перезарядку, затем создаёт `Projectile` и прикладывает отдачу. Все три оружия создают физические снаряды. CCD и дополнительная swept-sphere проверка уменьшают риск пролёта сквозь тонкие цели. Взрыв проверяет перекрытие радиуса и препятствия, применяет импульс один раз на Rigidbody и урон один раз на цель. Тяжёлый снаряд отскакивает и взрывается по таймеру.

## Испытания и результаты

`ChallengeManager` — общая модель сессии: Free → Countdown → Running → Results. Владелец явно назначен; ворота и цели передают экземпляр машины для проверки участника. Гонка завершается после последовательности ворот. Стрельба заканчивается по таймеру или уничтожению всех целей. Боевая трасса использует те же ворота и цели, добавляя штрафы к времени. HUD только отображает состояние и вызывает команды. `LocalRecords` сохраняет пять лучших результатов отдельно для каждого режима в PlayerPrefs. Тестовый прогон отключает сохранение рекордов.

`PlaygroundHud` — временный IMGUI интерфейс с масштабированием. Жёлтый маркер — прогноз первой точки столкновения баллистической траектории; белый прицел показывает направление наведения. Для отскакивающего снаряда прогноз заканчивается первым контактом.

## Следующий сетевой этап

Netcode for GameObjects и Unity Transport уже находятся в проекте. Новая сцена пока **локальная**: флаги Authority — границы исполнения, а не реализация сетевой безопасности. Имеющаяся панель `TankNetworkLobby` проверяет соединение старого прототипа; к новой сцене она не подключена.

Предполагается авторитетный сервер: клиент отправляет пронумерованные команды движения, направление наведения и запросы выстрела; сервер проверяет владельца, диапазоны значений, частоту запросов и перезарядку. Только сервер симулирует урон, попадания, ворота, таймер и очки. Текущий participant нужно заменить реестром участников с отдельным состоянием прогресса; паузу локальной игры не переносить на сервер.

Сервер распространяет snapshots позиции/вращения, линейной и угловой скорости, башни, оружия и фазы матча; события создания/удаления снарядов, попаданий и результатов имеют сетевые идентификаторы. Удалённые экземпляры интерполируют снимки, не симулируют авторитетную физику. Предсказание локального управления и коррекция — отдельный этап. Детерминированный lockstep для PhysX не предполагается. PlayerPrefs не является доверенным источником соревновательных результатов.

## Ограничения альфы

Пока нет PvP, урона шасси, звука, деформации земли и пулов снарядов/эффектов. Точность учитывает уникальные идентификаторы попавших выстрелов: один взрыв, задевший несколько целей, считается одним попаданием. Настройка подвески и силы оружия требует дальнейших игровых заездов.
