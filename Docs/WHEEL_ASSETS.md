# Подготовка геометрии колёс T100

Сначала приводим к единому стандарту сами колёса, затем настраиваем их расположение и физический радиус. Усложнение подвески не исправляет неверный origin меша.

## Что обнаружено в исходнике

Исходник: `Assets/ASEED/Stylized Tactical Vehicle/Source/T100_FREE.fbx`. Геометрия прочитана через Blender 4.3.2. С учётом исходного масштаба:

| Колесо | Смещение центра геометрии от origin вдоль оси | Подготовленный файл |
| --- | --- | --- |
| `SM_Wheel_1`, переднее левое | около 0,2125 м | `Wheel_FL.fbx` |
| `SM_Wheel_2`, переднее правое | около 2,1264 м | `Wheel_FR.fbx` |
| `SM_Wheel_3`, заднее левое | около 0,2125 м | `Wheel_RL.fbx` |
| `SM_Wheel_4`, заднее правое | около 2,1264 м | `Wheel_RR.fbx` |

У `SM_Wheel_1` дополнительно есть одна вершина, не принадлежащая ни одной грани, далеко от колеса. Она увеличивает габарит меша и портит автоматическое центрирование. Поэтому сначала удалена свободная геометрия, затем вычислен центр по габаритам оставшейся сетки. Это исправление данных меша, не смещение дочернего Transform во время игры.

## Подготовленные ресурсы

- Рабочий файл: `Assets/_ThirdPartyLocal/T100/Wheels/Source~/T100_Wheels.blend`.
- Четыре FBX: `Assets/_ThirdPartyLocal/T100/Wheels/Wheel_FL.fbx`, `Wheel_FR.fbx`, `Wheel_RL.fbx`, `Wheel_RR.fbx`.
- Сведения о преобразовании: `Assets/_ThirdPartyLocal/T100/Wheels/Source~/preparation.json`.

В `.blend` четыре сцены: `Wheel_FL`, `Wheel_FR`, `Wheel_RL`, `Wheel_RR`. Переключатель сцен находится в верхней панели Blender. В каждой одно колесо, центрированное в мировом начале. У объектов Location = 0, Rotation = 0, Scale = 1. Ось вращения — X; единицы — метры. Исходный размер, левая/правая геометрия и UV сохранены. Трансформации импорта запечены в сетку. При экспорте FBX применяется перевод в Y-up; тангенты должен рассчитывать Unity после триангуляции, поскольку исходная сетка содержит n-gon.

Размер каждого подготовленного колеса: примерно 0,512091 м по ширине и 1,092309 м по диаметру. Радиус — **0,5461545 м**. Этот радиус задан в префабе T100.

Исходный FBX ASEED не изменён. Подготовленные файлы — производные лицензированного набора, хранящиеся в Git вместе с оригиналом, текстурой и материалами. Подпапка `Source~` служит для редактируемого исходника, а в Unity используются отдельные FBX. Имя `_ThirdPartyLocal` сохранено для совместимости путей и скрипта; папка больше не исключена из Git. После клонирования подготовка в Blender не нужна. Исключена только автоматическая резервная копия `.blend1`.

## Установка вместо исходных мешей

В [префабе T100](../Assets/MadMachines/Vehicles/T100.prefab) четыре MeshFilter ссылаются на подготовленные FBX. Четыре `Wheel Definitions` задают опоры T100. Точки `Wheel anchor` в редакторе показывают исходное собранное положение колёс относительно кузова. У объектов с мешами локальные Position и Rotation равны 0, Scale равен 1. Откройте префаб для настройки и запустите Playground для проверки в движении.

Положение взято из prefab ASEED с учётом центра используемых вершин каждого меша и смещения `Body visuals (1)` на −1,5 м по Y:

| Параметр | T100 в Playground |
| --- | --- |
| Колея по центрам колёс | 1,913932 м: X = ±0,956966 |
| Колёсная база | 3,4277473 м |
| Передняя ось | Z = 1,7126635 |
| Задняя ось | Z = −1,7150838 |
| Высота центров в исходной сборке | Y = −0,94772243 относительно шасси |
| Высота физических точек `Mount` | Y = −0,35903493 |

`Mount` задаёт положение ступицы при полном сжатии, поэтому его Y отличается от высоты колеса в собранной машине. При текущей массе 1250 кг, четырёх пружинах по 49000 Н/м и ускорении падения 1,2 × 9,81 м/с² статическое сжатие на ровной дороге составляет примерно 7,5 см. При полном ходе 0,65 м остаётся примерно 0,575 м от `Mount` до центра колеса. Значение рассчитано по параметрам префаба и требует проверки в Play Mode.

Следующие шаги нужны для другой или более старой копии сцены. Работайте вне Play Mode. Для первой проверки достаточно существующих `Wheel anchor`, рычажные узлы устанавливать не требуется.

1. Дождитесь импорта четырёх FBX. В настройках импорта сохраняйте единичный Scale Factor и единицы файла, импорт нормалей и расчёт тангентов. Не добавляйте коллайдеры.
2. Раскройте соответствующий FBX в Project и назначьте его **Mesh** в существующий `MeshFilter` объекта колеса. Это заменяет сетку и сохраняет назначенный `MeshRenderer` с материалом T100. Не требуется добавлять целый FBX-prefab поверх прежнего колеса.
3. Соответствие: `Wheel anchor 0` → FL, `1` → FR, `2` → RL, `3` → RR. После установки рычагов тот же MeshFilter находится под `Wheel spin`.
4. У объекта с MeshFilter установите локальные Position = 0, Rotation = 0, Scale = 1. У `Wheel spin`, если он есть, также не должно быть корректирующего смещения или масштаба. Начальное вращение — 0. Исправленная геометрия уже центрирована и ориентирована.
5. Для сохранения реального размера колеса задайте физический радиус **0,5461545**: в каждой опоре `Wheel Definitions/Radius`, а если список ещё пустой — в прежнем поле `VehiclePhysics/Wheel Radius`. Размещение центров колёс задавайте через `Mount` физической опоры. Это положение ступиц на машине, а не компенсация ошибок ассета.
6. Сохраните сцену после проверки. Подготовка FBX сама по себе не переназначает MeshFilter существующего Playground.

Если игре нужен диаметр 0,86 м, вместо большого колеса можно осознанно уменьшить геометрию в Blender и применить масштаб перед экспортом; тогда физический радиус остаётся 0,43 м. Не смешивайте размер одного варианта с физическим радиусом другого.

## Как сделать вручную в Blender

Для такой работы достаточно Object Mode и Edit Mode; моделировать колесо заново не нужно.

1. Импортируйте FBX и выберите одно колесо. Перейдите в Edit Mode (`Tab`), выделите всё (`A`) и выполните **Mesh → Clean Up → Delete Loose**. Вернитесь в Object Mode.
2. Выполните **Object → Apply → Rotation & Scale**. Это переносит импортные поворот и масштаб в геометрию.
3. Выполните **Object → Set Origin → Origin to Geometry**; в параметрах операции выберите **Bounds Center**. Для этого ассета после удаления одиночной вершины центр габарита подходит. У других моделей несимметричные выступы могут потребовать выбора центра оси по геометрии обода.
4. В панели `N → Item` задайте Location = 0 по трём осям. При правильном origin весь объект окажется в начале координат. **Apply Location до центрирования не решает задачу:** он запекает положение в вершины, оставляя смещённый меш.
5. Убедитесь, что ось колеса — X. Если нужна коррекция направления, поверните объект и снова примените только Rotation. Для экспорта выбирайте одно колесо: FBX, Selected Objects, тип Mesh, Forward −Z, Up Y, Apply Transform, без анимации. В подготовленных файлах эти действия уже выполнены.

Справка Blender: [origin объекта](https://docs.blender.org/manual/en/5.1/scene_layout/object/origin.html), [применение трансформаций](https://docs.blender.org/manual/en/5.0/scene_layout/object/editing/apply.html).

## Повторная подготовка

Из корня репозитория; исходный пакет уже входит в клон:

```bash
blender --background --factory-startup --python Tools/Art/prepare_t100_wheels.py
```

Скрипт не перезаписывает существующие результаты. Для другой папки добавьте `-- --output /полный/путь`. Параметр `--overwrite` намеренно заменяет результаты, включая ручные изменения `.blend`; используйте его только для пересоздания из оригинала. В стандартной папке скрипт сохраняет GUID четырёх FBX, на которые ссылается Playground; при первом создании записывает их в `.meta` до появления FBX. При нестандартной папке фиксированные GUID не назначаются, чтобы не создавать дубликаты. Скрипт не запускает Unity и не изменяет исходный пакет, сцену или игровую логику.

## Проверка пользователем

Префаб ссылается на идентификаторы уже импортированных ресурсов Unity. Тесты, сборка и Play Mode агентом не запускались. Визуальная проверка остаётся пользователю.

- После назначения убедитесь, что правая и левая пары стоят симметрично относительно физических точек, диски обращены наружу, материалы и рисунок шины сохранились.
- Сравните центры колёс с арками спереди, сзади и сбоку. После входа в Play Mode база и колея должны оставаться заданными для T100, а после оседания на ровной поверхности — сохраняться исходная высота относительно арок. Проверьте отсутствие задевания кузова при рулении и ходе подвески.
- Поверните отдельное колесо вокруг локальной X: оно должно вращаться на месте. Поворот родительской точки вокруг Y должен происходить около центра колеса, без облёта вокруг машины. После проверки верните углы в 0.
- В Play Mode проверьте контакт с землёй при выбранном радиусе, руление обеих сторон, ход подвески, движение вперёд/назад и восстановление. Вращение при езде требует ранее реализованного `Wheel spin`; для проверки origin достаточно ручного поворота в редакторе.
