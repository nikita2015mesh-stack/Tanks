# Сервер Mad Machines

12 ноября 2026 года пользователь подтвердил запуск «Трёх дорог» вдвоём на двух машинах с MX Linux. Журнал сервера фиксирует две заявки, загрузку карты, создание двух машин и начало сессии `2/2`. Переподключение после обрыва и отмену при загрузке предстоит проверить отдельно.

## Сервер на Windows 11

1. Остановите Play Mode и выберите **Tools → Mad Machines → Networking → Собрать сервер для Windows**. Unity публикует `MadMachinesServer.exe` в `Builds/Network/Match-WindowsServer/versions/`. Если редактору не хватает поддержки Windows Server, откройте **File → Build Profiles → Add Build Profile → Windows Server** и установите предложенный модуль через Unity Hub. [Документация Unity](https://docs.unity3d.com/6000.6/Documentation/Manual/dedicated-server-build.html).
2. Запустите последнюю опубликованную сборку из корня проекта в PowerShell.

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File Tools/Network/Start-WindowsLanServer.ps1
   ```

   Скрипт покажет путь к `server.log` и команду остановки для второго окна PowerShell. Дождитесь `LOBBY_READY` в журнале. По умолчанию сервер слушает все IPv4-интерфейсы. Для проверки только на этой машине добавьте `-BindAddress 127.0.0.1`.
3. Запустите `FrontEnd` в Play Mode и укажите `127.0.0.1` и порт `7777`. Дождитесь зелёного индикатора. На втором клиенте из той же версии проекта укажите LAN-адрес Windows-машины, если он запущен на другом компьютере. Для входящих LAN-подключений серверу нужны UDP 7777 и 7778 в брандмауэре Windows.
4. Нажмите «В бой» по очереди на обоих клиентах. После первого должно появиться `1/2`, после второго — загрузиться «Три дороги». В журнале ожидаются `SERVER_READY` и две записи `joined with vehicle`.

## Два компьютера в LAN на MX Linux

На рабочей машине запускаем сервер матчей и клиент из `FrontEnd` в Unity. На соседней запускаем готовый Linux-клиент. Соберите обе роли из одной версии проекта. Прогон проверяет связь, очередь и полный матч на «Трёх дорогах». [Сценарии Deathmatch](DEATHMATCH_PLAN.md#ручная-проверка).

1. На рабочей машине в Unity 6000.6.8f1 соберите сервер через **Tools → Mad Machines → Networking → Собрать сервер для Linux** и клиент через **Tools → Mad Machines → Build Linux player**. Соберите их из одного состояния проекта. Для сервера нужен модуль [Linux Dedicated Server Build Support](https://docs.unity3d.com/6000.0/Documentation/Manual/dedicated-server-requirements.html).
2. Из корня проекта запустите сервер.

   ```bash
   bash Tools/Network/Start-LinuxLanServer.sh
   ```

   Скрипт запускает последнюю опубликованную сборку сервера матчей, выводит журнал в терминал и сохраняет его в файл. Команда остановки выводится при запуске. По умолчанию сервер слушает все IPv4-интерфейсы. Чтобы слушать только один адрес, передайте его аргументом.
3. Здесь откройте `FrontEnd` в Play Mode. На соседнюю машину скопируйте весь каталог `Builds/MadMachines-Linux/` и запустите из него `./MadMachines.x86_64 -logFile "$PWD/client.log"`.
4. Используйте порт `7777`. На рабочей машине адрес по умолчанию `127.0.0.1`, на соседней введите LAN-адрес рабочей машины и нажмите «Сохранить адрес». Клиенты подключаются в фоне. Дождитесь зелёного индикатора.
5. Нажмите «В бой» сначала на одном клиенте. Должно появиться ожидание `1/2`. Нажмите «В бой» на втором. Сервер загрузит «Три дороги» и создаст машины, когда оба клиента подключатся к карте.

Проверьте отмену заявки и переход в гараж при `1/2`. Перезапустите сервер при открытом главном и проверьте, что связь восстановилась без новой заявки. Затем проверьте два разных старта, видимость и плавность движения обеих машин, столкновение, выстрел и попадание. При отмене во время загрузки второй клиент должен вернуться к ожиданию. Для повторного запуска выйдите на главный обоими клиентами и снова подайте две заявки.

При сбое сохраните журнал сервера, Console первого клиента и `client.log` второго. `LOBBY_READY` означает готовность очереди на UDP 7778. После двух заявок ожидаются `SERVER_READY` с `three_roads_01` на UDP 7777 и две записи `joined with vehicle`.

## Проверки в редакторе

**Tools → Mad Machines → Networking → Проверки** содержит проверку ссылок сцен, политики команд и состояния запущенной сессии. Сцена [NetworkSandbox](../Assets/MadMachines/Networking/Scenes/NetworkSandbox.unity) доступна напрямую из Project. Настройки её подключения находятся в **Preferences → Mad Machines → Networking**. Файл `UserSettings/MadMachines.Networking.json` хранится локально.

## Серверная симуляция

- Сервер владеет сетевыми объектами машин и снарядов. У машины отдельно реплицируется ID управляющего клиента. Сервер сверяет ID отправителя из транспорта с назначением и проверяет, что клиент подключён. В Deathmatch при обрыве машина остаётся на карте без управления. При переподключении сервер возвращает участнику управление или возрождает машину и сохраняет счёт по билету матча. На сетевом полигоне при обрыве машина удаляется.
- Сетевые prefab используют `NetworkPhysicsState` с серверными правами записи. В их иерархиях запрещены `NetworkTransform` и `NetworkRigidbody`, поэтому у объекта нет RPC `SetState`. В NGO 2.13.3 `ParentSyncMessage` отдельно применяет смену родителя и позу. Для серверных объектов отключены оба пути через `AutoObjectParentSync` и `SyncOwnerTransformWhenParented`. Вывод основан на чтении исходников пакета.
- Клиент отправляет пронумерованные газ, руление, ручник, направление и запрос огня на каждом шаге 50 Гц. Сервер проверяет отправителя, значения, порядок и частоту (60 команд/с с запасом для пачки). За шаг применяет одну команду движения из очереди до четырёх записей. При переполнении отбрасывает самую старую. Если очередь пуста, продолжает последний ввод до тайм-аута 250 мс, затем тормозит. Короткий запрос огня сохраняется до физического шага, наведение берётся из последней принятой команды.
- Сервер использует `WeaponSystem` для наведения, перезарядки и отдачи штатной баллистической пушки. Полёт, взрыв и попадания симулирует `Projectile`. Снаряд живёт до 6 с и может завершить полёт после ухода стрелявшего. Клиенты показывают вспышку и взрыв по событиям сервера. На клиенте тела кинематические, коллайдер снаряда и физика машины выключены.
- Снимок содержит позу кузова, углы башни, состояние опор и время завершённого физического шага с его номером. В протоколе 9 добавлены линейная и угловая скорости, скорости вращения опор, ID управляющего клиента и номер последней команды, применённой к движению. `NetworkPhysicsSnapshotLoop` захватывает состояние после физики перед `PreUpdate` NGO. NetworkVariable отправляется на 30 Гц.
- Клиент интерполирует чужие машины со сдвигом 100 мс и удерживает последний снимок при нехватке данных. Своя машина использует локальное предсказание. При выключении предсказания по F9 или нехватке истории для согласования она переходит на ту же интерполяцию.

## Плавность движения — стадия 1

На этой стадии появились физические временные метки снимков и сравнение камер по F8. На текущей версии проверку можно начать с выключенным предсказанием по F9.

**Порядок проверки пользователем**

1. При необходимости выполнить **Tools → Mad Machines → Networking → Проверки → Проверить интерполяцию снимков**. Это проверки буфера на неравномерных временных интервалах, удержании/возобновлении, очистке истории и переходе вращения через 360°. Они не проверяют реальный порядок PlayerLoop, PhysX или сеть. Старый пункт **Run command policy checks** остаётся отдельной проверкой политики команд и протокола.
2. Запустить отдельный сервер и два клиента. На ровной прямой сравнить свою и чужую машину при постоянном газе, разгоне, торможении, заднем ходе, повороте и ручнике. Повторить по склону, через гребень и после приземления.
3. **F8** циклически переключает сетевую камеру: обычное сглаживание → прямое слежение → фиксированная позиция → обычное сглаживание. В фиксированной позиции мышь продолжает поворачивать взгляд. При появлении другой машины, в том числе после возрождения, восстанавливается обычная камера. Сравнивать на открытой площадке: неподвижная камера предназначена для наблюдения, машина может уехать из кадра.
4. Проверить стену, лобовое и боковое столкновение машин, отдачу, полёт/попадание снаряда и единственность урона. Проверить возрождение, переподключение, выход и повторный вход. Отдельно повторить Play Mode с отключённым Domain Reload, если этот режим используется: обработчик снимков не должен дублироваться.
5. Повторить с RTT около 50/100/200 мс, отдельно с jitter и небольшими потерями; отметить способ внесения задержки и фактический RTT из журнала. Сравнить при разных частотах кадров. Затем проверить одиночный заезд из гаража: езда, подвеска, камеры, оружие, восстановление и возврат.

Каждые 5 с клиент пишет `[MM NET SMOOTH]` для каждой машины: свою/чужую роль, RTT, номер последнего полученного физического шага, число полученных снимков и кадров, число переходов к удержанию и кадров удержания, минимальный запас буфера, максимальные интервалы получения и временных меток снимков, максимальное время кадра и число кадров с откатом часов. Счётчики и максимумы относятся к последнему окну около 5 с; текущие номер шага и размер буфера не сбрасываются. Удержание учитывается после получения хотя бы двух снимков. Отрицательный запас означает нехватку будущих данных для интерполяции. Тот же снимок диагностики доступен через **Inspect running session** в Editor.

При штатном сервере интервалы физических временных меток около 20/40 мс допустимы при отправке 30 Гц. Критерий стадии — отсутствие регулярных скачков видимой скорости на ровном участке и удержаний после заполнения буфера при нормальной LAN.

## Предсказание собственной машины — стадия 2

Пользователь проверил езду одной машины и оценил результат как хороший. Проверка с двумя участниками матча ещё впереди.

Пересобрать сервер и оба клиента из одной версии. Текущая версия протокола — **10**, с обновлёнными событиями выстрела, попадания и столкновения для звука и эффектов. Предсказание включено по умолчанию, F9 переключает его для сравнения при той же сети и камере. Для честного сравнения отпускать управление и останавливаться перед переключением, поскольку отображаемая позиция меняется между текущим предсказанием и задержанной интерполяцией.

1. Запустить **Run command policy checks** и **Проверить интерполяцию снимков** из меню сетевых проверок. Проверка команд включает применение пачки по шагам, переполнение очереди, истечение срока и короткий огонь.
2. На двух клиентах повторить одинаковый старт, отпускание газа, задний ход, поворот и ручник с F9 в обоих положениях. Проверить разные приводы. При RTT около 50/100/200 мс собственная машина должна реагировать без ожидания снимка, чужая — продолжать плавно двигаться.
3. Проехать склоны и гребни, приземлиться после прыжка, уткнуться в стену, столкнуться с машиной и получить попадание. Следить за величиной коррекций, положением кузова относительно стен и единичностью выстрела и урона. Локальная сцена моделирует статическую карту. Столкновение с другой машиной, попадание и отдача отображаются после авторитетной коррекции.
4. Проверить паузу, потерю фокуса, кратковременные потери пакетов, возрождение, переподключение и выход. При отсутствии подтверждений на протяжении 24 шагов клиент переходит на интерполяцию. После получения подтверждения отброшенных команд предсказание возобновляется. После возрождения журнал должен показать новую машину и новую историю. Повторить одиночный заезд с торможением, столкновением, стрельбой и восстановлением.

Журнал `[MM NET PREDICT]` показывает число накопленных команд, согласований, повторённых шагов, резких коррекций и максимальную ошибку позы за окно. На ровной дороге при стабильной сети ожидается быстрый отклик без регулярных резких коррекций. Для подбора порогов сохранить журналы двух клиентов, RTT, маршрут и режим F9.

## Дополнительные сценарии ручной проверки

| Сценарий | Что проверить |
| --- | --- |
| Сборка и процесс | Запуск до первой сборки, занятый UDP-порт, отмена сборки. При отмене опубликованная версия в `active.txt` сохраняется. |
| Ввод и стрельба | Короткий и удерживаемый огонь, стены и перекрытое дуло, исчезновение снаряда, единичное попадание, отдача и столкновение машин. При потере связи с зажатым газом сервер прекращает разгон после тайм-аута команд. |
| Переходы | При выключенном сервере запустить пробный заезд из гаража. После сетевой игры выйти на главный и проверить, что старая камера и машины убраны. |
