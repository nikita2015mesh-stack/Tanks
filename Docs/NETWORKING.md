# NETWORK 01 — выделенный сервер

**Статус: готово к проверке пользователем.** Unity, компиляция, сборки и Play Mode агентом не запускались. Работа трёх процессов ещё не подтверждена. Старый отчёт Playground этот код не проверяет.

Работа изолирована в ветке `feature/dedicated-server-01`, worktree `C:/Projects/Tanks/.worktrees/dedicated-server-01`. Открывайте в Unity именно этот каталог; основной проект можно продолжать редактировать отдельно. В worktree будет собственная Library. Не копируйте туда локальные сторонние модели: сетевой полигон использует примитивы.

## Схема и ответственность

```text
Клиент 1 (ввод, камера, HUD) ── команды UDP ──┐
                                            ├─ Dedicated Server: PhysX, оружие, попадания
Клиент 2 (ввод, камера, HUD) ── команды UDP ──┘
         ↑         серверные состояния машин, снарядов и счётчиков         ↑
```

- Сервер запускает `StartServer`, не `StartHost`, не занимает место игрока и не создаёт Camera, AudioListener или HUD. Только сервер создаёт/удаляет машины и снаряды. Два места резервируются при одобрении подключения, освобождаются при отключении; третьему клиенту отправляется причина отказа.
- `NetworkVehicle` адаптирует существующие `VehicleCommand` и `VehiclePhysics`. Исходная физика и одиночные компоненты не меняются. Сервер симулирует PhysX с шагом 0,02 с. На клиентах `VehiclePhysics` выключен, `NetworkRigidbody` делает Rigidbody кинематическими, серверный `NetworkTransform` интерполирует состояния, включая машину владельца. Сеть работает на 30 Гц.
- Команды содержат `uint Sequence`, газ/торможение, руление, ручник, единичное направление наведения и флаг огня. RPC разрешён владельцу; сервер дополнительно сверяет sender ID. Проверяются NaN/Infinity, диапазоны и длина направления. Устаревшие и повторные номера отбрасываются с учётом переполнения. Лимит — 40 команд/с с запасом на пачку из 8; клиент отправляет до 30/с. Через 250 мс без принятой команды сервер прекращает газ/огонь и включает ручник. Перезарядка 1,15 с измеряется сервером. Положение машины, стартовая точка снаряда и скорость от клиента не принимаются.
- Оружие намеренно имеет отдельный небольшой сетевой адаптер: локальный `WeaponSystem.RequestFire` непосредственно вызывает несетевой `Projectile.Launch` и графические эффекты. Его изменение затронуло бы Playground. Новая физика автомобиля не создавалась.
- Снаряд создаётся сервером: 38 м/с плюс скорость машины, гравитация, CCD и дополнительная проверка пути сферой, время жизни 6 с. При попадании сервер однократно прикладывает импульс 3200 Н·с, увеличивает счётчик попаданий машины, рассылает визуальную вспышку и удаляет снаряд. Отдача — 1600 Н·с. Стрельба сквозь стену при перекрытом дуле блокируется. Клиентский снаряд не имеет активного коллайдера.
- Цвет места, наведение, руление, положения четырёх примитивных колёс, скорость и счётчики выстрелов/попаданий реплицируются сервером. Существующая система внешнего вида, её колёса и T100 не используются и не меняются.

## Подготовка и сборка в Unity

1. Откройте worktree в **Unity 6000.6.8f1**, дождитесь импорта пакетов, проверьте Console. NGO зафиксирован в проекте на 2.13.3; используется входящий в зависимости Unity Transport.
2. Выполните **Tools → Mad Machines → Network → Create or open sandbox**. Эта команда создаст `Assets/MadMachines/Networking/Scenes/NetworkSandbox.unity` и `Networking/Generated/`: два сетевых prefab и семь материалов. Будут площадка с ограждением, три препятствия, две точки появления; машины создаёт сервер при подключении. Существующие сгенерированные файлы не перезаписываются. Генератор не запускается автоматически при импорте и не меняет Playground или общий список сцен.
3. Выполните **Build Windows client** в том же меню: результат `Builds/Network/Client/MadMachinesClient.exe`.
4. Выполните **Build Windows dedicated server**: результат `Builds/Network/WindowsServer/MadMachinesServer.exe`.

Собирайте обе роли из **одного набора сгенерированных ресурсов и их .meta**: NGO сверяет хеши prefab. При передаче проекта другому разработчику сохраните Generated, Scenes и их .meta вместе. Не генерируйте независимо prefab для клиента и сервера в разных копиях проекта.

Обе команды явно выбирают единственную сетевую сцену. Серверная команда использует `StandaloneBuildSubtarget.Server`, а не обычный Player с выключенной камерой; роль сервера автоматически выбирается по `UNITY_SERVER`. Нужны модули Windows Build Support и Windows Dedicated Server Build Support для этой версии Unity. При отсутствии модуля сборка завершится ошибкой с указанием проверить поддержку платформы; обычный клиент не выдаётся за серверную сборку.

Альтернатива — пользователь запускает сборку из PowerShell при закрытом редакторе **этого worktree**:

```powershell
Set-Location 'C:/Projects/Tanks/.worktrees/dedicated-server-01'
$unity = 'C:/Program Files/Unity/Hub/Editor/6000.6.8f1/Editor/Unity.exe'
$project = (Get-Location).Path
New-Item -ItemType Directory -Path Logs -Force | Out-Null
& $unity -batchmode -nographics -quit -projectPath $project -buildTarget Win64 -standaloneBuildSubtarget Player -executeMethod MadMachines.Networking.Editor.NetworkSandboxEditor.BuildWindowsClient -logFile "$project/Logs/network-build-client.log"
& $unity -batchmode -nographics -quit -projectPath $project -buildTarget Win64 -standaloneBuildSubtarget Server -executeMethod MadMachines.Networking.Editor.NetworkSandboxEditor.BuildWindowsServer -logFile "$project/Logs/network-build-server.log"
```

Дождитесь окончания каждой сборки и проверьте её журнал перед запуском следующей. Если Unity установлена иначе, замените `$unity`. Сцена создастся при первой сборке, если её ещё нет. Это инструкции, а не уже выполненные сборки.

## Три отдельных процесса локально

После успешных сборок выполните из worktree:

```powershell
$project = (Get-Location).Path
New-Item -ItemType Directory -Path Logs -Force | Out-Null
$stopFile = Join-Path $project 'Logs/network-server.stop'
# Только перед новым запуском: убрать оставшийся сигнал предыдущей остановки.
if (Test-Path -LiteralPath $stopFile) { Remove-Item -LiteralPath $stopFile }
$server = Start-Process -FilePath "$project/Builds/Network/WindowsServer/MadMachinesServer.exe" -WindowStyle Hidden -PassThru -ArgumentList @('-batchmode', '-nographics', '-mm-bind', '0.0.0.0', '-mm-port', '7777', '-mm-stop-file', ('"' + $stopFile + '"'), '-logFile', ('"' + "$project/Logs/network-server.log" + '"'))
```

Дождитесь строки **`[MM NET] Сервер готов`** в `Logs/network-server.log`, затем:

```powershell
$client1 = Start-Process -FilePath "$project/Builds/Network/Client/MadMachinesClient.exe" -PassThru -ArgumentList @('-mm-address', '127.0.0.1', '-mm-port', '7777', '-screen-fullscreen', '0', '-screen-width', '960', '-screen-height', '640', '-logFile', ('"' + "$project/Logs/network-client-1.log" + '"'))
$client2 = Start-Process -FilePath "$project/Builds/Network/Client/MadMachinesClient.exe" -PassThru -ArgumentList @('-mm-address', '127.0.0.1', '-mm-port', '7777', '-screen-fullscreen', '0', '-screen-width', '960', '-screen-height', '640', '-logFile', ('"' + "$project/Logs/network-client-2.log" + '"'))
```

Клиенты подключаются автоматически. В HUD есть IPv4, порт, статус, локальный ID, RTT (при наличии измерения), скорость и счётчики. **WASD**, **Пробел**, мышь и **ЛКМ** управляют собственной машиной. **Esc** освобождает курсор; кнопка «Вернуться к управлению» захватывает его снова. Потеря фокуса/выход из управления отправляет нейтральную команду с ручником; сервер и второй игрок продолжают работать. Для переподключения используйте кнопки «Отключиться» / «Подключиться».

Штатная остановка из той же PowerShell-сессии:

```powershell
New-Item -ItemType File -Path $stopFile -Force | Out-Null
$server.WaitForExit()
```

Сервер раз в секунду проверяет файл, завершает NGO-сессию, пишет сообщения об остановке и выходит. Файл остаётся на диске; перед следующим запуском удалите его. Принудительное убийство процесса тоже следует проверить как потерю соединения, но оно не гарантирует запись завершающего журнала. Сигнал остановки не является сетевой административной командой.

## Адрес, порт, LAN

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `-mm-address` | `127.0.0.1` | Числовой IPv4 сервера для клиента |
| `-mm-port` | `7777` | UDP-порт 1–65535, одинаковый у всех процессов |
| `-mm-bind` | `0.0.0.0` | Интерфейс прослушивания сервера; `127.0.0.1` ограничит локальным ПК |
| `-mm-stop-file` | не задан | Путь к локальному файлу штатной остановки сервера |
| `-mm-server` | выключен | Серверная роль для диагностики; в Dedicated Server уже включена независимо от аргументов |

Для LAN замените `127.0.0.1` у обоих клиентов на IPv4 серверного компьютера, например `192.168.1.20`. Разрешите входящий UDP 7777 для серверного процесса в брандмауэре. Клиенты используют собственные исходящие порты и могут работать на одной машине. Для публичного IPv4 понадобятся доступный UDP-порт и, если сервер за роутером, ручной проброс. DNS-имена, IPv6, Relay и NAT traversal этим срезом не реализованы.

## Ручная проверка A–E

Переходите к следующему этапу только после проверки предыдущего. Сохраняйте журналы всех трёх процессов и короткое видео обоих экранов; записывайте commit и версию Unity рядом с результатом.

1. **A — соединение.** Запустите Dedicated Server без окон и два клиента. В журнале сервера — два разных ID, два назначения места и две машины; собственного игрока у сервера нет. На клиентах статус «Подключено». Третий клиент получает понятный отказ. Также проверьте ошибочный адрес и занятый порт сервера.
2. **B — две машины.** На одном клиенте двигайтесь и рулите; второй наблюдает ту же оранжевую/синюю машину. Затем поменяйтесь окнами. Управление только собственное, чужая машина не реагирует на клавиши. Убедитесь, что ручник и задний ход работают. Alt+Tab/Esc не останавливают сервер, газ и огонь прекращаются.
3. **C — столкновения.** Разгонитесь навстречу друг другу, затем столкните машину с препятствием и пройдите трамплин. Оба экрана должны показывать одинаковое последующее положение с небольшой задержкой интерполяции. Окончательный результат определяется сервером.
4. **D — снаряд.** Наведитесь на вторую машину и стреляйте. На обоих экранах должны быть один и тот же летящий снаряд, падение под действием гравитации, исчезновение при попадании и толчок машины. Счётчик попаданий цели увеличивается один раз; сервер пишет ID снаряда и цели. Удержание ЛКМ не превышает темп одного выстрела за 1,15 с. Проверьте промах, тонкое препятствие, перекрытое дуло, исчезновение снаряда через 6 с и отключение стрелявшего клиента до попадания.
5. **E — жизненный цикл.** Отключите первый клиент, убедитесь на втором и в журнале, что его машина исчезла. Подключите снова: занято прежнее свободное место, всего две машины, дубликатов нет. Повторите несколько раз. Остановите сервер файлом-сигналом: процесс должен завершиться, клиенты — перейти в отключённое состояние и освободить курсор. Перезапустите сервер и подключите оба клиента кнопкой.
6. Повторите базовые A–D по LAN. Отдельно проверьте резкий разрыв связи/аварийное завершение: клиент ожидает таймаут транспорта, затем показывает отключение. При повышенной задержке оцените плавность и задержку ввода; предсказания пока нет.

В редакторе можно проверить одну роль: открыть NetworkSandbox и нажать Play (по умолчанию клиент); для сервера заранее включить `Server In Editor` на `Network session`. Для клиентского Play Mode выберите обычный Player subtarget, чтобы в редакторе не действовал `UNITY_SERVER`. Это вспомогательный сценарий, он не заменяет проверку отдельных сборок. Флаг `Server In Editor` не влияет на собранный клиент. Команду старого `PlaygroundEditor.BuildAndVerify` для сетевого среза не используйте: она проверяет другую сцену.

## Что просмотрено статически

- Сопоставлены используемые API с исходниками установленного NGO 2.13.3 / UnityTransport: RPC permissions, server authority, кинематические клиентские Rigidbody, регистрация prefab до старта, approval, callbacks остановки, RTT. Это чтение кода, не компиляция.
- Просмотрены границы авторитета, проверка чисел/номеров/частоты, таймаут ввода, жизненный цикл машин и снарядов, пути генерации и сборки. Выполнен `git diff --check`.
- Изменения ограничены новым `Assets/MadMachines/Networking` с `.meta`, этим документом и сетевой заметкой CURRENT_STATE. В основной рабочей копии не изменены ветка, Playground, визуальная система, колёса и сторонние ресурсы.
- **Не выполнены:** импорт Unity, C# / NGO IL postprocessing, генерация сцены, сборки Windows/Linux, тесты, Play Mode, запуск процессов, LAN и визуальная проверка. Реальные результаты всех сценариев выше пока ожидаются от пользователя.

Основания выбора компонентов: [физика NGO](https://mp-docs.dl.it.unity3d.com/netcode/1.13.0/advanced-topics/physics/) и [Dedicated Server subtarget](https://docs.unity3d.com/6000.0/Documentation/Manual/dedicated-server-build.html). Точные сигнатуры сверялись с локальным пакетом, а не только с документацией другой версии.

## Ограничения и следующий этап

Это отдельный технический полигон на двух игроков. Нет prediction, reconciliation, rollback/lag compensation, матчей, здоровья/уничтожения шасси, восстановления перевёрнутой машины, аккаунтов, шифрования/аутентификации, защиты от транспортного DoS, оптимизации трафика и миграции сервера. Попадания пока означают импульс и счётчик, не полноценный боевой урон. Для восстановления перевёрнутой машины переподключите клиента. Визуальные вспышки не сохраняются для позднего подключения; состояние машин и счётчики сохраняются в пределах текущей машины. Короткий запрос огня повторяется 100 мс, но при потере всех этих UDP-пакетов выстрел не гарантирован. Интерполяция добавляет задержку даже собственной машине. При занятой другой машиной точке появления возможно физическое пересечение на старте — защита места появления остаётся будущей задачей.

**Для VPS:** установить Linux Dedicated Server Build Support, выполнить **Build Linux dedicated server**, скопировать всю папку `Builds/Network/LinuxServer`, дать исполняемому файлу право запуска и запустить `./MadMachinesServer.x86_64 -batchmode -nographics -mm-bind 0.0.0.0 -mm-port 7777 -logFile ./server.log`. Нужны подходящий x86_64 Linux, разрешённый UDP-порт в ОС и панели провайдера, служба запуска/перезапуска, сбор журналов и наблюдение за нагрузкой. Linux-сборка и VPS не проверены. Сервис можно штатно останавливать тем же `-mm-stop-file`; учтите очистку файла при новом запуске. Relay и платные облачные игровые сервисы не нужны.

**Для полноценного PvP:** сначала подтвердить A–E, затем добавить серверную модель урона/матча и восстановление, обработку задержки и потерь (prediction/reconciliation, lag compensation), защиту места появления, версионирование протокола/ресурсов, нагрузочные и злоумышленные сценарии, аутентификацию и эксплуатационную защиту. Эти функции в NETWORK 01 не входят.
