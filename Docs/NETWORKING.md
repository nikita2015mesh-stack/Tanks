# Сетевой полигон Mad Machines

**Сетевой полигон входит в `main`.** Запуск Windows Dedicated Server, подключение одного клиента из редактора и восстановление соединения после перезапуска подтверждены пользователем 9 ноября 2026 года на интеграционной версии `27a4be5`. На объединённом `main` (`28a7850`) пользователь подтвердил работу. Журнал фиксирует готовность сервера, подключение одного клиента и серверный выстрел. При первом запуске в LAN сервер слушал `0.0.0.0:7777`, но подключился только локальный клиент. Проверка второго ПК отложена. Брандмауэр остаётся рабочей гипотезой.

В текущем NetworkSandbox используется [вариант общей T100](../Assets/MadMachines/Networking/Generated/NetworkVehicle.prefab) со штатной баллистической пушкой. Результаты выше относятся к прежней машине полигона. Для T100 предстоит прогон с двумя клиентами.

## Локальный запуск

Откройте **корень проекта** в Unity **6000.6.8f1** и дождитесь импорта. Для первой проверки нужны модули **Windows Build Support** и **Windows Dedicated Server Build Support**. Все команды ниже находятся в **Tools → Mad Machines → Networking**.

1. Выполните **Build Development Server**. Сцена NetworkSandbox и её prefab входят в Git. Если в редакторе открыт только чистый Untitled, NetworkSandbox откроется на его месте. Если у Untitled есть правки, сохраните сцену перед сборкой.
2. Выполните **Start Development Server**. Дождитесь «Сервер готов» в Console или проверьте **Development Server Status**. Ожидаемый адрес по умолчанию — `127.0.0.1:7777/UDP`.
3. Выполните **Create or open sandbox** и нажмите **Play**. Убедитесь, что `Server In Editor` выключен. Клиент должен подключиться автоматически и показать одну управляемую машину. Проверьте WASD, задний ход, пробел, мышь и ЛКМ. Esc освобождает курсор, кнопка в HUD возвращает управление.
4. Оставьте Play Mode включённым и выполните **Stop Development Server**. Дождитесь завершения процесса. Клиент должен перейти в ожидание, убрать старую машину и отпустить курсор.
5. Выполните **Restart Development Server**. Клиент должен сам подключиться к новой сессии и получить ровно одну машину. Повторите перезапуск уже запущенного сервера. Кнопка «Отключиться» в HUD должна остановить автоповторы до явного подключения.
6. Для второго игрока заранее выполните **Build Windows client**. Откройте опубликованный `MadMachinesClient.exe` из пути в Console. При изменённом локальном порте передайте `-mm-port <порт>` или задайте его в HUD. Проверьте две разные машины, управление каждой со своего клиента, стрельбу, столкновения, отключение и повторный вход второго клиента.

Альтернативный старт для проверки отсутствующего сервера. Войдите в Play Mode до шага 2 и дождитесь первого статуса ожидания. Затем запустите сервер и проверьте, что клиент сам подключился. Сохраните номер коммита, журналы и результат ручного прогона. Команды Unity, сборки и Play Mode агентом не запускались.

## Режимы и параметры

Команда **Development Settings** открывает локальные настройки редактора. Файл `UserSettings/MadMachines.Networking.json` исключён из Git. Настройки подключения читаются при входе в Play Mode. При смене локального порта перезапустите сервер и заново войдите в Play Mode.

| Режим | Поведение |
| --- | --- |
| **Offline** | Обычный Playground работает автономно. NetworkSandbox ждёт явного подключения через HUD. |
| **Development Online** | NetworkSandbox в Play Mode автоматически подключается к `127.0.0.1` на заданном локальном UDP-порту. Это режим по умолчанию. |
| **Remote Online** | NetworkSandbox автоматически подключается к удалённому числовому IPv4 и UDP-порту из настроек. |

Собранный клиент по умолчанию использует `127.0.0.1:7777`. Для переопределения используйте HUD или аргументы `-mm-mode offline|development|remote`, `-mm-address <IPv4>` и `-mm-port <порт>`. Для отдельного сервера доступны `-mm-bind <IPv4>`, `-mm-port <порт>` и `-mm-stop-file <путь>`. Сервер из меню привязан к loopback. При прямом запуске Dedicated Server без `-mm-bind` используется `0.0.0.0`.

Клиент повторяет подключение с паузой в две секунды после неудачной попытки или разрыва и ждёт, пока NGO завершит прежнюю сессию. Время обнаружения обрыва транспорта может достигать нескольких секунд. После входа заново создаётся игровая сессия.

Протокол приложения **5**, идентификаторы двух префабов и идентификатор карты передаются при approval. Сервер сообщает причину несовместимости, клиент прекращает автоповторы. При повторном закрытии до approval со стороны старого сервера клиент предложит проверить версии и журналы. Для новых версий меняйте `NetworkSessionProtocol.Version`, сохраняя параметры рукопожатия NGO, пока совместима его форма. Собирайте обе роли из одной версии проекта с общими ресурсами машины, снаряда и сцены.

## Карьер по сети

1. Выполните **Tools → Mad Machines → Quarry → Validate online assets**, затем **Quarry → Build Development Server** и **Quarry → Build Windows client**.
2. Выполните **Tools → Mad Machines → Networking → Restart Development Server**. Команда запустит последнюю опубликованную сборку сервера. В журнале готовности ожидается `map quarry.v2`.
3. Откройте **Quarry → Open online**, нажмите Play и запустите опубликованный клиент. Для локального прогона обе роли подключаются к `127.0.0.1:7777` по умолчанию. Обычные команды сборки в разделе **Networking** публикуют NetworkSandbox, команды в разделе **Quarry** публикуют карьер.

Сервер и клиенты загружают [QuarryOnline.unity](../Assets/MadMachines/Scenes/QuarryOnline.unity), которая использует тот же рельеф, что и локальный карьер. Для проверки подвески обе машины могут проехать рядом вверх от ремонтной базы. [Маршрут первого заезда](QUARRY_PLAN.md#первый-заезд)

## Сборки и управление процессом

| Команда | Действие |
| --- | --- |
| **Build Development Server** | Собирает Windows Dedicated Server штатным подтипом Unity Server. |
| **Start Development Server** | Запускает опубликованную сборку отдельным процессом. Проверяет активный процесс этого проекта и доступность локального UDP-порта. |
| **Stop Development Server** | Создаёт stop-файл конкретного запуска. Сервер закрывает сетевую сессию, затем выходит. При задержке команда сообщает путь к журналу. |
| **Restart Development Server** | Ждёт завершения старого процесса и запускает опубликованную сборку. Работает и после ручной остановки. |
| **Build and Restart Development Server** | Публикует новую сборку и перезапускает сервер после успешной сборки. При отмене или ошибке прежний процесс продолжает работать. |
| **Development Server Status** | Показывает состояние, PID, UDP-порт и путь к журналу. Данные запуска сохраняются при перезагрузке домена редактора. |
| **Build Windows client**, **Build Linux dedicated server** | Собирают NetworkSandbox для соответствующей платформы. Для Linux установите модуль Dedicated Server Build Support. |

Выходы находятся в `Builds/Network/<WindowsServer|Client|LinuxServer>/versions/<id>/`. В `active.txt` хранится идентификатор последней опубликованной сборки для платформы. Неудачная сборка не меняет этот файл. Прежние каталоги сохраняются, в том числе если их использует работающий процесс. [Руководство Unity по сборке Dedicated Server](https://docs.unity3d.com/6000.0/Documentation/Manual/dedicated-server-build.html).

Выделенный сервер пишет собственную диагностику на английском. Метка готовности в консоли и файле журнала — `[MM NET] SERVER_READY`. Редактор сохраняет журналы в `Logs/Network/Development/<id>/server.log`. При закрытии редактора отдельный процесс продолжает работать. После открытия того же worktree его можно остановить через меню. Если процесс завершился с ошибкой, путь к его журналу доступен в **Development Server Status**.

Существующий [PowerShell-сценарий](../Tools/Network/Start-LocalSandbox.ps1) запускает опубликованные Windows-сборки сервера и двух клиентов. Перед запуском остановите сервер из меню либо выберите другой порт через `-Port`.

```powershell
$run = & ./Tools/Network/Start-LocalSandbox.ps1
New-Item -ItemType File -Path $run.StopFile -Force | Out-Null
$run.Server.WaitForExit()
```

Первая строка запускает процессы. Последние две выполните, когда захотите завершить сервер.

## Серверная симуляция

- Сервер владеет сетевыми объектами машин и снарядов. У машины отдельно реплицируется ID управляющего клиента. Сервер сверяет ID отправителя из транспорта с назначением и проверяет, что клиент подключён. При разрыве сервер удаляет машину и освобождает одно из двух мест.
- Сетевые prefab используют `NetworkPhysicsState` с серверными правами записи. В их иерархиях запрещены `NetworkTransform` и `NetworkRigidbody`, поэтому у объекта нет RPC `SetState`. В NGO 2.13.3 `ParentSyncMessage` отдельно применяет смену родителя и позу. Для серверных объектов отключены оба пути через `AutoObjectParentSync` и `SyncOwnerTransformWhenParented`. Вывод основан на чтении исходников пакета.
- Клиент отправляет газ, руление, ручник, направление и запрос огня до 30 раз/с. Сервер проверяет диапазоны, конечность чисел, последовательность и частоту, затем передаёт последнюю допустимую команду в существующий `VehiclePhysics` перед физическим шагом 50 Гц. Через 250 мс без принятой команды газ и огонь сбрасываются, включается ручник. Короткий запрос огня сохраняется до физического шага в пределах того же тайм-аута.
- Сервер использует `WeaponSystem` для наведения, перезарядки и отдачи штатной баллистической пушки. Полёт, взрыв и попадания симулирует `Projectile`. Снаряд живёт до 6 с и может завершить полёт после ухода стрелявшего. Клиенты показывают вспышку и взрыв по событиям сервера. На клиенте тела кинематические, коллайдер снаряда и физика машины выключены.
- Снимок на тике 30 Гц содержит позу кузова, углы башни, ход, руление и вращение каждой опоры. Клиент интерполирует их вместе с задержкой 100 мс и применяет состояние опор через `VehicleVisuals`. Это касается и своей машины. Камера дополнительно сглаживает перемещение. Пользователь отметил ощущение запаздывания при первом прогоне на прежней машине. На T100 предстоит проверить задержку и плавность при низком RTT. Используется надёжная доставка NGO. При задержке клиент удерживает последний известный снимок.

## Дополнительные сценарии ручной проверки

| Сценарий | Что проверить |
| --- | --- |
| Два клиента | Разные ID, места и машины. Отключение второго клиента освобождает место. Третий получает сообщение о занятых местах. |
| Сборка и процесс | Ошибка до первой сборки, повторный Start, занятый UDP-порт, состояние после перезагрузки домена. Проверьте, что отмена сборки не останавливает сервер и не меняет `active.txt`. |
| Несовместимость | В отдельной копии тех же ресурсов измените только `NetworkSessionProtocol.Version` и соберите Windows Client. Клиент должен показать обе версии и прекратить автоповторы. С прежним NETWORK 02 ожидается общее сообщение после повторного раннего отказа. |
| Ввод и стрельба | Короткий и удерживаемый огонь, стены и перекрытое дуло, промах и исчезновение снаряда, единичное попадание, отдача, трамплин и столкновение машин. При потере пакетов ввода с зажатым газом сервер прекращает разгон после тайм-аута команд. |
| Режимы | Offline не соединяется сам и оставляет доступным одиночный Playground. Remote Online использует настроенный адрес и порт. При смене сцены камера и сетевые объекты исчезают. |

Команда **Validate sandbox assets** проверяет ссылки сгенерированных ресурсов. В подменю **Checks** доступны **Run command policy checks** для локальной проверки политики команд, интерполяции и рукопожатия, а также **Inspect running session** для снимка запущенной сессии. **Send invalid commands from client** и **Request client teleport** запускаются вручную в подключённом Editor-клиенте. Во второй проверке ожидается ошибка прав записи NGO. Выключите Error Pause и убедитесь, что локальная подмена исчезает на следующем кадре, а сервер и второй клиент сохраняют авторитетную позу.

При прогоне двух клиентов отдельно проверьте ход и вращение колёс и работу рычагов на подъёме карьера у обеих T100, попадание в другую машину, дульную вспышку, взрыв и переподключение. [План карьера](QUARRY_PLAN.md#первый-заезд)

## Вход из общего гаража

Основная сборка теперь начинается с FrontEnd. В гараже выберите привод T100, «По сети», IPv4 сервера и игровой порт, затем «Найти сессию». Ответ сообщает карту, режим, фазу и места; «Присоединиться» загружает нужную сетевую сцену. Карьер использует идентификатор `quarry.v2`, полигон — `sandbox`. Сейчас сервер обслуживает одну свободную езду на двух игроков, присоединяться можно во время сессии.

Пересоберите обе роли: код использует протокол **6**, добавлена личная конфигурация привода. Сервер допускает только предусмотренные варианты и создаёт каждому клиенту отдельную машину. При прямом запуске сетевой сцены без общего гаража остаётся привод префаба.

Для обычного игрового UDP 7777 дополнительно нужен UDP 7778 (информационный порт всегда игровой + 1). Откройте/пробросьте оба порта на сервере. Информационный запрос не занимает игровое место. Сведения действуют ограниченное время; окончательную доступность проверяет сервер при подключении. Если дополнительный порт недоступен, общий гараж не получит сессию; прямое подключение из сетевой сцены сохранено для разработки.

На подключённом клиенте описание сессии обновляется раз в секунду сообщением сервера. «В гараж» прекращает переподключение, завершает транспорт и выгружает сетевую сцену; второй игрок продолжает ездить. [Полная ручная проверка](CURRENT_STATE.md#единый-вход-и-личный-гараж). Изменения не проверены запуском агентом.
