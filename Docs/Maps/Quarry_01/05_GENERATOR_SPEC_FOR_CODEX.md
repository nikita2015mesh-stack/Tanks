# ТЗ для Codex: Unity Quarry Generator, этап A (v0.1)

## Контекст

Игра `Tanks` — многопользовательская игра с машинами. Сетевая игра — основной смысл, поэтому генератор НЕ должен разрушать существующую сеть, сцену, движение и существующие префабы. Репозиторий знает собственные AGENTS.md и Docs: перед реализацией читать их и следовать установленной архитектуре.

## Цель первого PR

Сделать **неразрушающий инструмент редактора Unity** для создания тестовой сцены карьера из подготовленной 16-битной RAW heightmap. Создание нового ландшафта должно быть повторяемым и проверяемым, без загрузки AI-моделей, облачных запросов или обязательного внешнего софта.

## Входной пакет

- `quarry_01.json` — единые метры, координаты и дорожные параметры.
- `Quarry_01_heightmap_le.raw` — 1025×1025, R16 little-endian.
- `04_POPULATION.yaml` — требования к будущему наполнению; YAML parser не обязателен в первом PR.
- `Quarry_01_layout.png` — образец размещения основных трасс.
- Документы 01/02/03 объясняют замысел и ограничения.

## Функциональность этапа A (в порядке приоритета)

1. Добавить в `Assets/Editor/` (или в принятую в проекте папку для editor-кода) команду меню `Tools/Tanks/Generate Quarry_01`.
2. До выполнения проверить входные файлы: размер R16 1025×1025×2 байта; высоты в заданных границах; не перезаписывать пользовательскую сцену или объекты молча.
3. Создать новую отдельную сцену `Quarry_01_Prototype.unity` либо сгенерировать terrain prefab/additive scene, не трогая существующую игровую сцену без явного подтверждения пользователя.
4. Создать TerrainData с `heightmapResolution=1025`, `size=(1500,210,1500)`, загрузить значение каждого R16 пикселя в нормализованную высоту `0..1`, правильно ориентировать Z.
5. Добавить Terrain Collider, простое освещение/skybox из текущего URP проекта, временные материалы земли. Не вводить лишних third-party зависимостей.
6. Создать маркеры старта A и B и крупные placeholders для промышленных ориентиров, опираясь на `quarry_01.json`.
7. Режим Preview/Generate должен быть идемпотентен: повторное создание не даёт копий сотен объектов, не ломает версионирование сцены.
8. Добавить проверку: файл читается, масштаб сохранён, TerrainCollider существует, спавны находятся внутри terrain, маршрут M0 не пересекает отрицательную высоту, стартовая сцена проекта сохраняется.
9. Если в проекте есть реализация транспорта, добавить способ временно переключаться на тестовую карту и проверять езду; без вмешательства в текущую сетевую архитектуру. При отсутствии готового загрузчика сцен — вывести понятные ручные инструкции.
10. Обновить `Docs/CURRENT_STATE.md` и, при существенных решениях, `Docs/ARCHITECTURE.md`, не подменяя существующие решения.

## Этап B — только после первого проезда

- Создать визуальную road mask по геометрии дорог из JSON, текстурирование проездов и породы.
- Placeholders из `04_POPULATION.yaml`, правило «не ставить камень на дорогу или рядом со спавном».
- Более реалистичная геометрия отдельных скалистых стен с Mesh Collider.
- Дополнительные перемычки S1/S2/S3, измерение реального доступа с учётом машины.
- Улучшить асимметрию без разрушения проходимости.

## Этап C — перспектива

- Поддержка параметрического пересчёта heightmap внутри Unity, UI редактора, сохранение seed.
- Разрушаемость локальных объектов, воронки, колеи, сетевые события изменения мира.
- По желанию отдельно подключать ИИ для генерации новых исходных концептов/layout, но **не** как зависимость игрового клиента.

## Приёмочные критерии первого PR

- [ ] В Unity генерация выполняется без ошибок редактора.
- [ ] Исходная сцена и текущий игровой процесс не повреждены.
- [ ] Террейн имеет размеры 1500×210×1500 метров и ожидаемый профиль.
- [ ] На карте видны непрерывная спираль и четыре кольцевых проезда по форме рельефа.
- [ ] Старт A и старт B совпадают с layout/JSON, корректная ориентация Z.
- [ ] Можно вывести существующую машину и проехать от дна к краю по M0.
- [ ] Проезд по тестовому маршруту не создаёт фатальных коллизий; ручной замер уклонов и поперечного крена приложен к результату.
- [ ] Никаких новых обязательных сервисов, платежей и постоянного третьего сервера.
- [ ] Повторная генерация воспроизводима, результат документирован.

## Не пытаться решить одним PR

Не реализовывать сразу ML-генератор, бесконечные процедурные миры, 3D-воксели, полноценную технику или синхронизацию тысячи сетевых объектов. Цель первого этапа — **въехать на большую, осмысленно устроенную карту и проверить ощущения**.

## Как сообщить об ограничениях

Если физика текущего транспорта не позволяет двигаться по уклонам, сообщить причину отдельно от генератора и предложить минимальный корректирующий патч. Никаких заявлений «всё работает», пока маршрут не проехали в редакторе настоящей машиной.
