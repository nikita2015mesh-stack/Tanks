# Quarry_01 — схема высот и импорт в Unity (v0.1)

## Файлы

- `Quarry_01_heightmap_16bit.png` — PNG 16-bit grayscale, 1025 × 1025.
- `Quarry_01_heightmap_le.raw` — RAW R16, little-endian, 1025 × 1025, без заголовка.
- `Quarry_01_heightmap_preview.png` — демонстрационная **8-битная** контрастная карта высот, **не для импорта**.
- `Quarry_01_cross_section.png` — поперечный профиль по Z = 750 м.
- `Quarry_01_relief_topview.png` — оттенённый рельеф с дорогами.

## Высота и единицы

Физические координаты: X=0..1500 м; Z=0..1500 м; Y=0..210 м (диапазон heightmap). Дно Y≈0 м; верхняя промышленная площадка ~180 м; нерегулярность земли может добавить несколько метров. Значение пикселя в R16:

`pixel = round(clamp(height_m / 210.0, 0, 1) * 65535)`

Для восстановления метров: `height_m = pixel / 65535 * 210`.

### Генерация

`generate_quarry_reference.py` строит высоту процедурно из `quarry_01.json`:

1. Исходные границы карьера (эллиптическая, слегка неровная чаша).
2. Восемь ступеней рельефа с мягкими вертикальными переходами.
3. Отдельная высота основной спиральной дороги, зависящая от положения вдоль трассы.
4. Кольцевые дороги, привязанные по высоте к ближайшим пересечениям со спиралью.
5. Сглаживающий коридор вокруг дорог: покрытие ровное, бровка постепенно переходит в окружающий рельеф.
6. Незначительная нерегулярность незаасфальтированных участков.

**Это не просто случайный шум.** Приоритет отдаётся проезжаемости и читаемой форме карьера. Поперечные уклоны и стыковки с иными маршрутами должны быть проверены в Unity.

## Импорт в Unity

В Unity Terrain можно работать с картами высот, но меню импорта может различаться по версии редактора/пакетов. Базовая последовательность:

1. В отдельной тестовой сцене создать Terrain.
2. Выбрать Import Raw в средствах Terrain Heightmap (конкретный интерфейс зависит от Unity).
3. Указать R16, 1025×1025, **Windows/little-endian** и правильную ориентацию изображения.
4. Terrain Size: X=1500 м, Y=210 м, Z=1500 м.
5. Начальная позиция Terrain: (0,0,0).
6. Временно добавить простейший материал породы, солнце и одну машину.
7. Пройти M0 и все кольцевые дороги; проверить уклоны и отсутствие провалов.

У RAW нет метаданных ориентации. Если после импорта рисунок оказался отражён по вертикали, использовать Flip Vertical (если доступно) или перевернуть строки файла перед импортом. Дорожный рисунок сравнивать с `Quarry_01_layout.png`, где +Z направлен вверх.

**Важный момент:** Unity не импортирует нарисованные цветом дороги из `layout.png` автоматически. В RAW зашита **их высотная форма**, а визуальные материалы дорог, спавны и объекты — отдельная задача генератора/сцены.

## Что heightmap может / не может

✅ Холмы, террасы, широкие пандусы, перепады высот, игровые зоны, базовая физическая поверхность.

⚠️ Почти вертикальные стены и нависающие скалы в heightfield выглядят ограниченно. При необходимости использовать отдельные Mesh с Collider. Для будущих тоннелей, подкопов, вырезания кусков стены или настоящего объёмного разрушения потребуется отдельный слой геометрии.

⚠️ Карта высот сама по себе не гарантирует отсутствие игровых тупиков, застреваний, неудачных прострелов или проблем FPS. Это проверяется в движке, с настоящим транспортным контроллером.

## Автоматические проверки исходного прототипа

Скрипт создаёт `road_checks.json`: примерные продольные уклоны по центральной линии (интервал измерения 10 м). Это только предварительная проверка и не заменяет 3D-валидацию и тесты на колёсах/гусеницах.

## Качество и следующий шаг

Разрешение 1025×1025 соответствует шагу сетки ~1,465 м/пиксель. Достаточно для **первого** проезда шириной 19–28 м, но не для детализированных колей и мелких кромок. Их надо делать декалями, дополнительными мешами или другим отдельным механизмом.

Для v0.2: дополнительные переходы, разные ширины террас, нерегулярные фронты выемки, участки скалы мешем, отдельные маски материалов, автоматическая проверка доступности всех ярусов.
