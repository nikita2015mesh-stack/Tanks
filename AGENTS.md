# Инструкции для работы с Mad Machines

Актуальная игра — **Mad Machines («Безумные машины»)**.
Рабочая область игры находится в `Assets/MadMachines/`.

## Что читать

Начни с [README.md](README.md) и [текущего состояния](Docs/CURRENT_STATE.md).
Затем открой только документы и исходники, нужные для задачи.

| Задача | Что открыть |
| --- | --- |
| Физика, управление, правила, сеть | [Архитектура](Docs/ARCHITECTURE.md) и исходники подсистемы |
| Графика, звук, импорт | [Видение](Docs/VISION.md) и [ресурсы](Docs/ASSETS.md) |
| Приоритеты и планирование | [Бэклог](Docs/BACKLOG.md) и [этапы](Docs/ROADMAP.md) |
| Поиск игровых механик | [Банк идей](Docs/IDEAS.md) |

Открывай `Docs/archive/` только по прямой ссылке или для задачи о прежнем прототипе.
Старые проверки и планы описывают другие версии и легко искажают оценку текущей игры.
В `Docs/decisions/` фиксируй только принятые решения, для которых важны причины и последствия.

## Как менять проект

- Сохраняй рабочие сценарии и совместимость. Новая механика не должна лишать игрока уже работающего управления, режима или результата без согласованного изменения.
- В C# используй четыре пробела и открывающую скобку на отдельной строке.
- Используй PascalCase для типов, методов и констант класса, camelCase для полей и локальных переменных.
- Для приватных настроек Inspector используй `[SerializeField]`.
- Сохраняй сериализованные имена полей, имена объектов, от которых зависят ссылки или поиск, и GUID ресурсов.
- Пиши новые внутриигровые тексты по-русски. Храни отображаемые названия отдельно от идентификаторов, имён файлов и ключей сохранения.
- При работе с прежним генератором следуй [инструкции прототипа](Docs/archive/T3485.md).

## Как проверять

- Все проверки выполняет пользователь. Самостоятельно не запускай тесты, сборки и Play Mode.
- Не используй Computer Use для работы с проектом.
- В итоговом сообщении укажи, какие сценарии нужно проверить. Команда Play Mode и сценарий ручной проверки описаны в [текущем состоянии](Docs/CURRENT_STATE.md).
- Сохранённый отчёт относится к конкретной версии. Приписывать его текущим изменениям нельзя.

## Git

- Проверь активную ветку и рабочее дерево перед изменениями. Сохраняй чужие правки.
- Пиши короткий заголовок коммита в повелительной форме.
- В PR указывай изменения, выполненные проверки и связанные задачи. Для видимых изменений приложи скриншоты или короткий ролик.
- Сливай изменения в `main` только по явному запросу.
